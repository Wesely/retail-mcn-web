# 詳細 User Story — 同場多品牌直播檔次（全生命週期）

> **這份文件是什麼**
> 從 `docs/master-brief.md` 推導出的**最複雜端到端場景**，作為兩條工作線的共同地基：
> - **Track 1 — Prototype**（`pages/prototype.html`）：把 §3「三視角切片」落成可切換視角的產品介面（寫死假資料）。
> - **Track 2 — System Design**（`proto/system-design.md`）：把 §4「資料物件清單」展開為概念資料模型、流程、狀態機。
>
> **為什麼選這條場景**：它是 brief 裡唯一同時點亮 **全部 5 個資料庫** + **直播前/中/後三段流程** + **最難的 5 條紅色 TBD（B1–B5）** + **含稅/未稅** + **Agent/Net 認列**的故事。其他需求都是它的子集。
>
> **資料皆為虛構 placeholder**：品牌、直播主、場地、數字全為示意，待真案例授權後替換（對齊 brief「案例全是 placeholder」原則）。本 prototype 為**內部工具**（同頁 3/4 性質），不受附錄 B 對外文案限制。

## §2. 端到端時序（直播前 / 中 / 後）

每一步標註：**觸發角色 · 碰哪個資料庫 · 踩哪條 TBD**。

### 直播前 — 選品 / 案型 / 排期
| # | 觸發角色 | 動作 | 資料庫 / TBD |
|---|---|---|---|
| 1 | 綠研所 / 膚光 / 暖窩 | 各自來談合作，提交商品明細 + 報價（含/未稅、供貨價、建議售價） | → **品牌庫**；`tax_inclusive` flag |
| 2 | 廠商管理 | 三品牌與商品建檔、打 Tag（品類/客群/適配主型態） | 品牌庫 ↔ **Tag table** |
| 3 | 企劃 / AI | 用 Tag 把「Bella × 這三批商品」配對 | 直播主庫 ↔ 品牌庫（AI 配對） |
| 4 | 企劃 / AI | 為這場挑品、設計三個案型（買3送1 / 組合價 / 滿額禮）+ 銷量預估 | → **案型庫**（AI 模仿專家） |
| 5 | 企劃 | 定價與折扣，含稅/未稅換算 | 結算前置定價 |
| 6 | 場控 | 排定「信義 A 棚」（容納/格局/照片） | → **場地庫** |
| 7 | 企劃 | 建立檔次 `LS-0918`，掛上場地 + Bella + 三品牌選品清單 | **跨庫 join — 資料模型核心**（B4） |

### 直播中 — 場控 / 即時數據
| # | 觸發角色 | 動作 | 資料庫 / TBD |
|---|---|---|---|
| 8 | 直播主端介面 | Bella 登入看「9/18 這場要賣什麼」：三品牌商品卡 + 案型話術 + 售價 | 檔次唯讀視圖（渠道端關鍵 UI） |
| 9 | 場控 / 系統 | 直播流程與狀態管理、即時數據 | 場次**狀態機**（typical CRUD） |

### 直播後 — 對帳 / 結算 / 評分
| # | 觸發角色 | 動作 | 資料庫 / TBD |
|---|---|---|---|
| 10 | 品牌 + 渠道 | 雙邊回報數量；綠研所出貨 215 ≠ 渠道回報 210 → 開爭議單 | B2B 對帳；**爭議單狀態（B5）** |
| 11 | 系統 | 退貨進來，計算退貨損益歸屬 | **退貨歸屬（B2）** |
| 12 | 會計 / 系統 | 同場三品牌**分開歸戶**，各自算 GMV/退貨/淨/佣金 | **多品牌歸戶（B4）** |

## §4. 資料物件清單（→ 餵 Track 2 System Design）

| 物件 | 角色 | 關鍵欄位 / 關係 |
|---|---|---|
| **場地 Venue** | 場地庫 | 容納人數、格局、活動照片（不養護） |
| **品牌 Brand** | 品牌庫 | 名稱、Tag、聯絡 |
| **商品 Product** | 品牌庫 | 屬於 Brand；品類 Tag |
| **報價 Quote** | 品牌庫 | 屬於 Product；`tax_inclusive` flag、供貨價、建議售價 |
| **直播主 Creator** | 直播主庫 | Tag[]、分級 S/A/B/C、渠道 |
| **案型 DealType** | 案型庫 | 買N送M / 組合價 / 滿額禮；可被 AI 模仿生成 |
| **直播檔次 Session** | （聚合根） | 綁 1 Venue + 1 Creator + N 選品行；狀態機 |
| **選品行 LineItem** | Session 子物件 | Session × Product × DealType × 定價 |
| **結算行 SettlementLine** | 結算庫 | 歸戶單位 = **(Session × Brand)**（B4）；GMV/退貨/淨/take/分潤 |
| **爭議單 DisputeTicket** | 結算庫 | 出貨數 ≠ 回報數時開立；狀態（B5） |
| **場後評分 Scorecard** | AI 治理 | 屬於 Session × Brand；AI 生成 |

> **核心洞察**：`Session` 是橫跨五庫的**聚合根**；結算以 **(Session × Brand)** 為歸戶粒度——B4 一解，B1/B2/B3/B5 全部掛在這個粒度的欄位與狀態上。先用「同場多品牌」這個最複雜形狀設計，「同場單品牌」自動是退化情況，日後不用重構。

## §5. 分潤 / 利潤計算（Agent / Net）

### 公式（brief §2）
```
我方毛利 = 品牌讓價 + (take rate 8% × 佣金基數) − (場地 + 企劃 + 出貨協調 + 案型 成本)
我方營收認列 = 僅佣金（不認 GMV 全額；IFRS 15 Agent）
營業稅 5% 基數 = 佣金
直播主團隊 = 淨GMV − 品牌供貨成本 − 我方 take
品牌方     = 供貨價 × 售出數 − 退貨
```

### 本場 worked example（placeholder）
| 項目 | 數字 | 說明 |
|---|---|---|
| 淨 GMV | 318,000 | 三品牌合計（扣退貨後） |
| 我方佣金（營收） | **25,440** | 318,000 × 8%；唯一認列的營收 |
| 品牌供貨成本（估） | ~171,700 | 加權供貨/售價比 ~54% |
| 直播主團隊淨分潤 | **~120,860** | 318,000 − 171,700 − 25,440 |

> 直播主團隊淨分潤含主播個人抽成 + 團隊營運成本，本場景不再細拆。

> ⚠️ **佣金基數假設**：本場景示範以**淨 GMV（扣退貨後）**為 take rate 基數。但「gross GMV vs net-of-returns」屬 **B1/B2 待決**——system design（Track 2）需把佣金基數設為**可配置欄位**，不寫死。
