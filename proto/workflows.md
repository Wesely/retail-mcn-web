# 三角色工作流程 — User Scenarios（prototype 藍圖）

> **設計轉向**：原本的原型把每個角色做成「結果儀表板」（看數字），**那不是要的**。
> 這份文件改拆解每個角色**實際在系統裡一步步做的事**——表單、選擇、排程、登錄等「動作」——
> 作為 workflow 型 prototype 的藍圖。原本的成績/結算畫面降級為各流程的**最後一步**（看結果），不浪費。
>
> **共同場景**：仍以 `proto/user-story.md` 的 LS-0918（Bella × 綠研所/膚光/暖窩 同場三品牌）為串接資料。
> **每個 scenario 的格式**：目的 → 操作畫面 → 輸入/輸出 → 碰的資料物件 → 對應 user-story / TBD。

---

## A. 廠商工作流程（綠研所視角）· 5 步

> 主線：把貨進系統 → 設好價 → 從行事曆看場次 → 出貨對帳 → 看結算。

### V1 · 建立品牌檔案
- **操作**：填公司基本資料、聯絡人、選品類 Tag → 送出建檔
- **輸入**：綠研所、保健品類、聯絡窗口
- **資料**：`Brand`（name, tags[], contact）
- **對應**：user-story §2 步驟 1

### V2 · 批次上架商品 + 設定報價　★核心
- **操作**：下載報價範本 → 填好 → **上傳 XLSX 一次匯入 N 筆** → 系統解析成「表格式報價清單」→ 逐列確認含稅/未稅 → 一次送審（亦可手動新增單筆）
- **輸入**：5 筆綠研所報價（益生菌 / 膠原蛋白飲 / 魚油 EPA / 葉黃素 / 維他命 C），各帶供貨價、建議售價、稅基
- **資料**：批次寫入 `Product` + `Quote`（每列 tax_inclusive flag）
- **對應**：user-story §2 步驟 1–2
- **為何 XLSX**：廠商常一次報數十筆,逐筆表單太慢;匯入後以表格檢視、逐列微調最直覺。

### V3 · 場次行事曆 → 該場商品清單　★核心（取代「確認參與場次」）
- **操作**：以**行事曆 VIEW** 看所有「有賣綠研所商品」的場次 → **點一場** → 看該場我們被播報的商品清單（商品 / 案型 / 售價 / 狀態）
- **輸入**：點 LS-0918 → 益生菌（買 3 送 1、$880、對帳中）
- **資料**：（讀）`Session[]` 依權限過濾 → 該場 `LineItem` where brand = 綠研所
- **對應**：user-story §2 步驟 3、8
- **資料隔離**：同一場只看得到自家商品,看不到同場其他品牌

### V4 · 出貨 + 對帳（合併;標記「可刪」）
- **操作**：① 登錄出貨數、上傳出貨單 → ② 系統與渠道回報比對,不符自動開爭議單
- **輸入**：出貨 215 / 回報 210 / 差異 5 → 爭議單 #D-0918-01（對帳中）
- **資料**：`SettlementLine.shipped` + `DisputeTicket`
- **對應**：user-story §2 步驟 10–11 · **TBD B5**
- **⚠ 可刪**：出貨 / 對帳可能改由企劃端統一處理或走外部流程;此步驟是否保留在廠商端待定。

### V5 · 看結算與成績（流程終點）
- **操作**：對帳結清後 → 看本品牌 GMV / 退貨 / 淨 / 結算狀態 + AI 場後評分
- **輸出**：GMV 180,000、退貨率 6.7%、淨 168,000、AI 評分
- **資料**：（讀）`SettlementLine` `Scorecard`
- **對應**：user-story §2 步驟 12–15 · **TBD B1**
- **資料隔離**：看不到其他品牌、take rate、直播主分級

---

> ### 🗓️ 場次行事曆 VIEW —— 跨三角色的核心 model
> `Session`（直播場次）貫穿三個角色,適合用一個**行事曆 VIEW** 呈現,依權限過濾顯示哪些場次,點任一場進該場細節（角色不同看到的切片不同）:
>
> | 角色 | 看得到的場次 | 點進去看到 |
> |---|---|---|
> | 廠商 | 所有「有賣他家商品」的場次 | 只看自家被播報的商品清單 |
> | 企劃 | 所有自己經手過的場次（建立 / 排程 / 結算） | 整場全貌（多品牌、結算、分潤） |
> | 直播主 | 所有自己參與播報的場次（一場可能 N 位主播合作） | 這場要賣什麼 + 自己的分潤 |
>
> 本原型已在**廠商 V3** 實作;企劃 / 直播主待套用同一 VIEW（之後處理那兩條流程時接上）。

## B. 企劃工作流程（我方，最完整）

> 主線：收報價 → 配主 → 選品組場 → 設案型定價 → 挑空場地排程 → 場控 → 對帳結算分潤。

### P1 · 品牌報價進件管理
- **操作**：審核廠商送來的報價 → 補打 Tag → 入品牌庫/商品庫
- **輸入**：綠研所/膚光/暖窩 三筆報價（含稅、未稅、含稅）
- **資料**：`Brand` `Product` `Quote`
- **對應**：user-story §2 步驟 1–2

### P2 · 直播主配對
- **操作**：用 Tag 篩直播主 → 比對「Bella × 這批商品」適配度（AI 建議）→ 發案
- **輸入**：選定 Bella（Tag 美妝·保健·女性25-45、A 級）
- **資料**：（讀）`Creator`；AI 配對
- **對應**：user-story §2 步驟 3

### P3 · 選品組場　★核心
- **操作**：開新場次草稿 → 從報價池**跨品牌挑商品**加入清單（益生菌 + 精華液 + 擴香組）
- **輸入**：3 品牌 3 商品組成 LS-0918 草稿
- **資料**：`Session`(草稿) + `LineItem[]`
- **對應**：user-story §2 步驟 4、7 · **TBD B4**

### P4 · 案型設計 + 定價
- **操作**：為每個選品套用/AI 生成案型 → 設定價 → **含稅/未稅自動換算**確認
- **輸入**：買3送1 / 2入組合$1,580(未稅→含稅$1,659) / 滿$1,000送香氛袋
- **資料**：`DealType` + `LineItem.unit_price`
- **對應**：user-story §2 步驟 4–5

### P5 · 挑選空場地 + 排程　★核心
- **操作**：查場地庫**可用狀態**（行事曆/清單）→ 挑一個「空的」場地 → 排入日期時間 → 場次狀態 草稿→已排程
- **輸入**：信義A棚（9/18 該時段空）、排 2026-09-18 20:00
- **資料**：（讀）`Venue` 可用性；`Session`(venue_id, scheduled_at, status=scheduled)
- **對應**：user-story §2 步驟 6–7

### P6 · 直播中場控
- **操作**：開播當天把場次切「直播中」→ 記錄即時數據/流程節點
- **輸入**：LS-0918 → status=直播中
- **資料**：`Session.status`
- **對應**：user-story §2 步驟 9

### P7 · 場後對帳 + 多品牌歸戶
- **操作**：收雙邊回報 → **逐品牌分開歸戶** → 比對出貨/回報 → 處理爭議單
- **輸入**：三品牌各自 GMV/退貨；綠研所爭議單 #D-0918-01
- **資料**：`SettlementLine[]`（每品牌一行）+ `DisputeTicket`
- **對應**：user-story §2 步驟 10–12 · **TBD B4 / B5**

### P8 · 結算 + 分潤 + 報表（流程終點）
- **操作**：選結算時機開佣金 → 算我方佣金/各方分潤 → AI 評分 → 出三視角報表
- **輸出**：我方佣金 25,440、直播主團隊淨分潤 ~120,860、各品牌評分
- **資料**：`SettlementLine.commission` `Scorecard`
- **對應**：user-story §2 步驟 13–15 · **TBD B1 / B2 / B3**

## C. 直播主工作流程（Bella 視角）

> 主線：建檔 → 收邀約接檔期 → 直播前備課 → 直播 → 看分潤。人到就好。

### H1 · 建立直播主檔案
- **操作**：填個人/團隊資料 → 選擅長品類 Tag → 綁頻道（FB/IG）
- **輸入**：Bella、Tag 美妝·保健、FB+IG
- **資料**：`Creator`（tags[], channels[]；grade 內部填,主播看不到）
- **對應**：user-story §1
- **資料隔離**：不顯示 S/A/B/C 分級

### H2 · 收到場次邀約 + 接受檔期
- **操作**：收到配對邀約 → 看場次摘要（日期/場地/品牌數/預估分潤）→ 接受或婉拒
- **輸入**：接受 LS-0918
- **資料**：（讀）`Session`；回寫接受
- **對應**：user-story §2 步驟 3

### H3 · 直播前備課
- **操作**：查看「這場要賣什麼」→ 逐品看案型話術、售價、賣點、商品圖
- **輸入**：益生菌(買3送1) / 精華液(組合$1,659) / 擴香(滿額禮)
- **資料**：（讀）`LineItem` `DealType` `Product`
- **對應**：user-story §2 步驟 8

### H4 · 直播中
- **操作**：開播 → 看商品順序與話術提示（場控由我方協調，主播只專注播）
- **資料**：（讀）`Session`(直播中)
- **對應**：user-story §2 步驟 9

### H5 · 看分潤（流程終點）
- **操作**：場後查本場團隊 GMV、淨分潤、結算狀態
- **輸出**：本場淨 GMV 318,000、團隊淨分潤 ~120,860、結算狀態（依 B1）
- **資料**：（讀）`SettlementLine`
- **對應**：user-story §2 步驟 15 · **TBD B1**
- **資料隔離**：看不到我方對品牌的讓價空間（**S1 防跳單**）

## D. Prototype 呈現方式（待確認後製作）

把上面每個角色的 scenario 串成一條**可逐步走過的流程**：
- 頂部選角色（廠商 / 企劃 / 直播主）；其下是該角色的**步驟導覽**（V1→V6 / P1→P8 / H1→H5）。
- 每一步是一個**擬真操作畫面**：表單欄位、商品挑選清單、場地可用行事曆、排程器、對帳表等——重點在「正在做這個動作」，不是看結果。
- 上一步/下一步可前後走；流程最後一步才是「看結果」（沿用原本做好的成績/結算畫面）。
- 仍寫死 LS-0918 假資料,讓三條流程串得起來。

> 步驟總數：廠商 6 + 企劃 8 + 直播主 5 = **19 個 scenario 畫面**。
