§1設計原則（不可違反的硬約束）

這些約束決定資料模型與系統邊界,任何實作不得違反。

B2B-only · 不碰 C 端

不接金流、不持顧客個資、不負客服;消費者側全在渠道／品牌之間。

brief §7.10
Agent / Net 認列

只認佣金為營收,不認 GMV 全額。模型必須能單獨算出「佣金」這個數。

brief §2 · §7.1
平台中立

不綁定任何收單系統（就醬播只是選項之一）。對接走 adapter,先期可手動匯入。

brief §7.9
含稅 / 未稅雙向

每個價格帶帶 tax_inclusive flag,系統自動換算另一邊。

brief §2
AI 不做決策

AI 做記錄、案型模仿、評分、建議;人拍板。條例歸案是基礎。

brief §7.7 · §12
分級內部 only

直播主分級 S/A/B/C 是 DB 欄位,對外不可見（外部只說 Tag 化配對）。

brief §7.8 · 附錄 B-10

§8落地：自建 vs 拼裝現成工具

技術可行性整體 🟢-🟡,無真正 blocker;最大不確定性在商業條款（B1-B5），不是工程題。因此不該一開始就重金自建。

子系統拼裝現成自建建議
五大資料庫 CRUDAirtable / NocoDB 易過度投資拼裝
Session 聚合 + 狀態機自動化勉強 中清楚但要工 可拼裝起步 → 痛了自建
結算 / 對帳 / 多品牌歸戶現成工具弱 難必要 可自建薄層（核心價值）
含稅 / 未稅換算公式欄位可 中簡單隨結算層自建
平台中立 adapter—每系統一個 中延後,先手動匯入
三視角 UI（原型）工具視圖醜 中自建前端 可階段 2 自建
CRM（品牌 / 直播主）HubSpot / Notion 易—拼裝
AI 治理Claude Code + Notion + Fireflies 易—拼裝
